# Мой проект об окончании второго курса

Данный проект представляет собой веб-приложение женского фитнес клуба. Данное приложение имеет бэкенд, фронтенд и базу данных

## Стек технологий

- Фронтенд: React + TS
- Бэкенд: Java Spring Boot + Hibernate
- Proxy: Go + Gin + yl2chen cidranger
- База данных SQL: PostgreSQL
- База данных NoSQL для proxy: MongoDB

## Краткое описание

В проекте реализовано:

1. Go-Proxy:
    - Rate limiting в зависимости от ip-адреса
    - Cache для некоторых запросов, а также его очистка
    - Бан для некотрых ip-адресов
    - Запись всей информации о запросах пользователя в базу данных MongoDB за исключением передаваемых данных в body HTTP-запроса
2. Java-Backend (основное):
    - Регистрация пользователя с проверкой на уникальность логина и email
    - Вход по логину и паролю
    - Изменение данных профиля пользователя
    - Смена пароля
    - Деактивация пользователя
    - Бронирование тренировок с проверкой на дату и количество свободных мест
    - Отмена бронирования с проверкой на время проведения тренировки
    - Создание тренировки
    - Назначение тренера тренировки
    - Изменение данных тренировки
    - Отмена тренировки
    - Заглушка оплаты (не будет реализовано полностью - проект учебный)
    - И многое другое, в том числе эндпоинты с методом GET
3. PostgreSQL - основная база данных для хранения информации о пользователях, тренировках и бронированиях
    - Присутствует всего 14 таблиц
    - Информация о пользователях разделена на 3 таблицы: users - логин, пароль; profile - данные профиля; roles - три роли (CLIENT, TRAINER, ADMINISTRATOR)
    - Информация о тренировках разделена на 4 таблицы: workouts - виды тренировок (например, йога, танцы); schedules - тренировки в расписании; workout_types - типы тренировок (CARDIO, DANCE и т.д.); rooms - залы для проведения тренировок
    - Информация о бронированиях разделена на 2 таблицы: bookings - сами бронирования; booking_statuses - статусы бронирования (ACCEPTED, PROCESSIND, CANCELLED, COMPLETED)
    - Информация об абонементах раделена на 3 таблицы: subscriptions - виды абонементов в клубе; client_subscriptions - абонементы у клиентов; subscription_statuses - статус абонементов у клиентов (ACTIVE, LAPSED, FROZEN)
    - Информация о платежах разделена на 2 таблицы: payments - информация о платежах клиентов; payment_statuses - статусы оплаты абонемента (ACCEPTED, PROCESSIND, CANCELLED)
4. React-Frontend - основной фронтенд для клиента. На данный моент реализовано:
    - Возможность регистрации
    - Возможность авторизации через логин и пароль
    - Возможность изменения данных профиля, кроме дня рождения
    - Изменение пароля
    - Бронирование тренировок
    - Приобретение абонементов, в том числе и нескольких
    - Отмена записи на тренировку 
5. React-Frontend-metrics будет описан позже
